# Limite graph operations and Vulkan coverage

## Scope and identities

This is source inventory, not execution or qualification evidence. The inspected target is `paradigma-inc/limite-1b-violetto` at HF revision [`9f4d1567975a44c35127503deadfe52d434d734f`](https://huggingface.co/paradigma-inc/limite-1b-violetto/tree/9f4d1567975a44c35127503deadfe52d434d734f), using the original plugin at [`7ddad34f5e3d25ddea68c6745fc00373b82bca21`](https://github.com/GreenYellowRedBlue/limite-violetto/tree/7ddad34f5e3d25ddea68c6745fc00373b82bca21), the immutable accepted brief at [`173c50ea1f11b4b68ad8eb350b40c8b464ae64d5`](https://github.com/GreenYellowRedBlue/limite-violetto/blob/173c50ea1f11b4b68ad8eb350b40c8b464ae64d5/docs/specs/limite-vulkan-spec.md), and candidate llama.cpp [`296538adea19ff397100bf8e7d71f302d2d2bb35`](https://github.com/ggml-org/llama.cpp/tree/296538adea19ff397100bf8e7d71f302d2d2bb35). Candidate source inspection does not select or qualify that dependency.

The complete cached original `src/llama-arch.cpp` and candidate `conversion/__init__.py` registries do not register the Limite architecture or `LimiteForCausalLM`. Architecture, conversion/model-loader mapping and graph construction therefore remain missing. The immutable review's header evidence is **743 tensors: 338 BF16 and 405 F32; 1,035,141,120 serialized BF16 values and 113,056 F32 values, including 288 zero-dimensional F32 scalars**. Do not substitute the brief's incomplete F32 count. Full checkpoint bytes were not downloaded or hash-verified; preserve original names/shapes/dtypes/rank independently of derived folded weights.

## Operation/evidence inventory

Classification: **Reuse** means a corresponding general GGML operation/pipeline exists in source; it is not proof for Limite's graph or exact numerical contract. **Conditional** requires exact type/shape/layout/device pipeline selection and numerical-boundary proof. **Missing** means model-specific registration, graph construction, or an operation not represented by the inspected generic paths.

Additional generic device constraints matter: support-op rejects tensors over device buffer/storage limits (`15340-15360`); matrix-matrix support has source-type/layout restrictions and rejects BF16×F16 (`15472-15488`). `supports_op` is only an eligibility predicate; pipeline selector can still return null for a particular op/type (`8760-8945`). Fusion is limited to listed graph patterns and their guards (`14353-14450`), and can change rounding unless explicitly controlled. Backend scheduling can otherwise leave unsupported nodes on CPU; startup must fail closed rather than silently falling back. The source inventory does not show this model's loaded graph, scheduler placement, selected pipelines, or execution.

## Future falsifying coverage checklist

Once an implementation exists, enumerate the loaded graph before dispatch: operation, dtype, dimensions/strides, backend, selected pipeline, fused pattern and fallback decision. Every required transformer/head compute operation must execute on Vulkan; fail startup for absent required pipelines, CPU transformer/head arithmetic, unsupported shapes or unaccounted conversion paths. Classify metadata-only views, transfers and allowed CPU tokenization/scheduling/sampling separately rather than prohibiting all host work. Compare coverage with every semantic family above, not just op names.

Exercise and retain diagnostics for:

- Every one of the 743 tensors: expected name, exact shape/rank/dtype, byte count; explicitly count all 288 rank-zero F32 scalars. Check load/reload preserves raw values and folding does not double-apply.
- Projection matrices for Q/K/V/O, MLP up/gate/down, tied head, embedding and both VE declared table layouts; BF16×BF16 and relevant BF16×F32 graph combinations, non-contiguous/transposed views, all actual batch/token dimensions.
- RMSNorm at stream/head widths including zeros, tiny/large values and dtype epsilon; BF16 output boundaries.
- RoPE positions 0, odd/even positions, pair 0/31 and untouched tail lanes; global no-RoPE and chunk/cache absolute-position transitions.
- VE enabled/disabled layers and stored-head layout variants; verify modified V is both attended and cached. Attention gates and XSA on each configured layer; verify five-query-head grouping, all ten alpha values and current post-VE V.
- Global and local attention with prefill/decode, batch and non-square chunks, empty/short/full history, exact 1,025-position local boundary, mask/scale, BF16 KV, FP32 accumulation and output rounding. Check selected backend and reject CPU fallback.
- MUDD layer 24/47 tap identities, history lifetime, both attention/R-way coefficient families, erf GELU and exact left-to-right accumulation with per-step rounding.
- SwiGLU component boundaries (up, gate, SiLU, multiply, down), no clamp, all activations and multiple token counts.
- Output all 151,680 rows, explicitly inspect 13 rows beyond 151,667 IDs, compare their logits and sampling/detokenization behavior to reference; verify raw-logit BF16 then FP32 softcap.
- Enumerate fusions and compare unfused/fused results against the numerical reference at every mandated rounding boundary; validate absent/unsupported-pipeline failure is fatal, never CPU fallback.

These are future checks, not results. This report ran no build, tests, GPU dispatch or qualification. Registry and source availability establish reusable building blocks only. **Question answered at source-inventory level:** substantial generic matrix, lookup, RoPE and attention mechanisms exist, but architecture/conversion/loading/graph support and several exact BF16/custom paths are absent or conditional. Downstream feasibility and numerical parity remain unvalidated.
