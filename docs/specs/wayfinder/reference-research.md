# CUDA reference capture and strict qualification prerequisites

Source research for [Define CUDA reference capture and qualification prerequisites](https://github.com/GreenYellowRedBlue/limite-violetto/issues/6), completed 2026-10-14. **The research question is answered; operational reference access, capture, repeatability, seed independence and downstream qualification are not established.** This is an operator-facing capture specification, not an implemented capture tool or measured result. It informs [Verify an operational CUDA reference capture bundle](https://github.com/GreenYellowRedBlue/limite-violetto/issues/12) and [Define the native token-control and serving conformance boundary](https://github.com/GreenYellowRedBlue/limite-violetto/issues/14).

Evidence labels: **source** means inspected code or official published material; **prior observation** means the immutable design review's recorded experiment, not a run performed here; **required/proposed** means an unexecuted process; **deduction** means conditional mathematical reasoning. No builds, tests, inference, hardware probes, dependency changes or provisioning were performed. The [map Notes][map] and accepted ADRs are binding.

## 2. Runtime and operator handoff

**Source requirements:** the root [quickstart][readme] specifies Linux x86-64, Python 3.12, NVIDIA GPU, an already-installed compatible driver, `uv sync --locked`, and `VLLM_PLUGINS=limite` serving; no separate CUDA toolkit is required for its ordinary wheel installation. Tagged vLLM [GPU requirements][vllmgpu] require Linux and [compute capability ≥7.5][vllmcuda]. That lower bound is not Violetto BF16 qualification for every listed GPU. NVIDIA [minor-version compatibility][driver] gives CUDA 13.x driver branch ≥580 with feature/PTX caveats; satisfying the branch alone is not a load or kernel-success result. The pinned [model card][card] reports native Transformers validation on H100, Python 3.12/Torch 2.11.0/Transformers 5.6.2, SDPA default, one whole replica per process, and rejects FlashAttention 2 + StaticCache. This is first-party reported support, not an H100 available here.

**Prior observation:** local `nvidia-smi` failed with insufficient permissions, Windows enumeration showed AMD only, no usable CUDA runner was established, no self-hosted GitHub runner or SSH host was discovered, and stopped WSL was not native Linux qualification. Do not rerun those checks merely to confirm failure. The accepted route is **operator-provided Linux/NVIDIA access**, with no implied permission to rent hardware, install global drivers, change boot configuration or substitute ROCm/CPU [review, hardware evidence][review].

**Required handoff before any pilot:**

1. Operator supplies an authorized Linux/NVIDIA execution allocation and named responsible person; records GPU model/compute capability/available memory, driver, OS/glibc, Python/uv versions, storage quota and permitted run duration. No minimum memory/runtime feasibility is claimed by this note.
2. Agree access mechanism and local-only/authenticated endpoint, output destination, transfer method, retention and permitted input classes. Transfer credentials privately; never include host secrets in issues, command logs or reports. Operator allocation/scheduler policy remains outside evaluator semantics [evaluation contract][evalcontract].
3. Supply immutable original source and root lock, an isolated environment and verified offline HF snapshot; record plugin source/wheel identity and reject dirty/unrecorded modifications. Operator must not accidentally sync the evaluator lock or launch its 0.28 runtime.
4. Predeclare pilot input inventory, request limits, context/output budgets, repeat count, restart/reset procedure and stopping conditions. Inputs and limits are frozen before outputs; use fresh immutable attempt directories. Capture a normal operational lane plus separately named diagnostic lanes, not a single blended bundle.
5. Return an indexed, hash-verified bundle with provenance and failures as well as successes. A consumer verifies transfer hashes and completeness before accepting it. Operator inability to expose a field is recorded as missing evidence, never filled from presumed defaults.

The README command uses a moving model name. **Required adaptation for audit:** serve the verified local immutable snapshot (or an explicit immutable revision supported by the pinned CLI), recording model/tokenizer/code revisions and resolved paths. This changes input pinning, not the accepted execution mode. Keep tensor/pipeline parallel sizes at one and retain ordinary compiler/graph selection. Record resolved settings rather than claiming omitted flags enforce any particular backend [readme][readme], [ADR-0003][adr3].

## 3. Artifact and input verification

**Source:** pinned HF [weight pointer page][weights] publishes SHA-256 `9dc7e89e30acf473629f98ac3ade535fb05cc044fe7e399b78d0bc957283a5f5` and a distinct Xet hash; the brief records size **2,070,811,520 bytes**, **743 tensors**, 1,035,141,120 BF16 values and an incomplete 112,768 F32 count [brief §1.2][brief]. The prior complete-header inventory records **113,056 F32 values, including 288 zero-dimensional scalars**; all must survive conversion. These are metadata/header facts, not complete weight-byte verification. Published weights/config/text assets match across the two HF revisions while native model/configuration code and card blobs differ: identical weights do not identify complete executables [review][review].

| Object | Required frozen evidence | Reject / falsifying check |
|---|---|---|
| Source and installed runtime | Full Git/HF revisions; source archive/tree identity; root manifest/lock digest; selected wheel filenames, complete-file digests and installed versions; plugin/loaded-module paths | Unexpected code, wheel or dependency; newer vLLM despite matching plugin name. |
| Complete checkpoint | Full-file SHA-256 and exact size against published identity; validated tensor names, dtype, shape and byte ranges, all 743 tensors; raw BF16/FP32 payload retained | Truncation, corruption, missing/unexpected/duplicate tensors, or header-only evidence represented as full verification. Xet/Git pointer hashes are not substitutes for payload SHA-256. |
| Text/model assets | Byte hash and presence/absence inventory for config, generation config, tokenizer JSON/config, special/added-token files, template, effective extra tokenizer files, native custom code; resolved auto-map and fallback selection | Hashes of revision strings instead of actual files; template/code selected from a moving revision; ignored added tokens/padded output rows. |
| Future native artifact | Independent artifact byte digest; converter revision/settings; complete mapping and inverse reconstruction proving lossless source dtype/value/shape/orientation/ties; raw versus folded weights identified | Reusing CUDA artifact hash for a different layout; lossy conversion; applying projection scales twice. |
| Numerical/API inputs | Original approved input or protected locator, exact rendered UTF-8 bytes, prompt token IDs, positions/masks, continuation IDs, request JSON, sampler/decode/stops/budgets; each item's digest and stable ID | Equal prompt counts or matching benchmark names without byte/ID identity; accidental chat-template duplication; reconstruction from completion text. |
| Quality corpus | Resolved dataset source/config/split/revision, actual ordered source rows and rendered inputs/gold, taskset/overlap memberships, declared rollouts/scorer anchor/fallback and unavailable graders | GSM8K still declared merely `unpinned`; omitted tasksets or licensing-driven silent corpus changes. |

Strict qualification must not reuse generic comparison acceptance: [ADR-0005][adr5] requires same verified source/lossless derivation and actual input semantics, while allowing only declared engine/build/layout differences. The existing [resolver][resolve] hashes `hf-hub:<identity>` for Hub inputs (not weights); local hashing covers config and top-level Safetensors. Existing [prepared-input identities][inputs] already hash ordered raw rows and rendered inputs and preserve scoring declarations: reuse those conventions, but retain recoverable frozen inputs, actual text-asset byte identities and full artifact evidence rather than treating digests alone as a new complete bundle. The review documents the generic comparator gaps and unpinned GSM8K resolution [review, strict qualification section][review]. Historical manifests remain unchanged.

## 4. Capture lanes and execution fingerprints

Every file needs a producer ID linking its source/assets, command/settings, execution profile, input IDs, dtype/shape/layout, capture point, output digest and attempt. **Required:** root operational logits/quality and serving responses come from ordinary supported execution. An instrumented/eager tensor dump is useful but separately labelled. Hooks can alter compilation, fusion and graph capture; compare its final outputs to the operational lane and report discrepancies rather than treating instrumented intermediates as automatically authoritative [ADR-0003][adr3].

Required profile record:

- Observed attention backend per applicable workload, selected kernels and relevant package/build identity; graph capture/replay versus eager, compiler mode/options, compiled artifacts/cache identity, actual prefill/decode batch and chunk shapes, padding and scheduling/concurrency.
- Model/activation/KV dtypes, BF16 narrowing sites, FP32 exceptions, `lm_head_precision_mode`, quantization disabled, TF32/matmul/reduced-precision/reduction settings where exposed, fusion behavior, seed/RNG policy; unset versus resolved values distinguished.
- GPU/compute capability/device identity (protected where necessary), driver, OS/kernel/glibc, Torch CUDA build/runtime and loaded CUDA/cuBLAS/cuDNN/FlashInfer/Triton libraries; command/environment allowlist, cache/prefix/chunked-prefill mode, warmup and restart state.
- Per-request execution/attempt IDs, seed/choice index, inputs, reset/cache/ordering state and actual batch membership. A single server-start log does not establish all per-request numerical profiles.

**Source anchors:** the root model is [compile-enabled][modeling]. Its attention consumes value-embedding-adjusted V; XSA is FP32 until narrowed correction; scalar folds narrow to weight dtype. Ordered BF16 MUDD additions are explicit [components][components]. Pinned config declares `oracle_exact`, BF16, 151,680 output rows and tokenizer vocabulary 151,667 [config][config]; root head code also has a distinct `fp32_accumulate` branch. Capture and verify the selected `oracle_exact` branch, not simply the output dtype. Source expressions do not prove compiled intermediate rounding. Native attention/cache selection remains a diagnostic fingerprint [card][card], [review][review].

## 5. Required fixtures, producers and repeatability

| Capture family | Minimum useful reference evidence / falsifying diagnostic |
|---|---|
| Canonical text/token fixtures | Canonical math system + user render, Unicode/LaTeX, rejected system/tool/role/content cases, `<think>`/`</think>`, special-token decoding, added-token IDs, padded/undefined IDs, multi-ID Unicode decoding. Retain exact render, input IDs, raw generated IDs and canonical final text separately. Prior 48-token canonical prompt and split Unicode observations are regression leads, not new serving measurements [review][review]. |
| Sampling/log probabilities | Greedy and sampled requests; explicit versus checkpoint defaults; temperature/top-p/top-k/min-p and all declared penalties individually and in combinations; `n` choices with explicit `seed + choice_index`; generated/top and prompt logprob values, associated IDs/ranks and normalizer/processing semantics. Synthetic-logit diagnostics isolate filtering/penalty order; do not infer logprobs from sampled token counts or silently compare reporting distributions to post-sampling distributions [brief §§4.1–4.2][brief], [ADR-0006][adr6]. |
| Termination/usage/transport | Non-streaming and SSE; EOS, explicit stop IDs, stop strings crossing token/chunk boundaries, include/exclude stop semantics, budget exhaustion, cancellation/disconnect and invalid requests; ordered events, finish/stop reasons, prompt/completion usage and accepted token prefix. Preserve raw reasoning without a parser. Generated IDs, emitted text and usage are distinct evidence [ADR-0004][adr4], [runner][runner]. CUDA serving fixtures inform the future native acknowledgement boundary; they do not establish it exists. |
| Numeric execution | Teacher-forced fixed IDs/positions: operational softcapped logits, selected prefill/cached decode comparisons; separate diagnostic intermediates around RMSNorm, folding, VE-adjusted V, local/global attention, XSA, both MUDD sites and head. Use positions around 1023/1024/1025, high absolute positions, unequal-length batches, legal chunk boundaries and total-context limits. Compare first divergent operation rather than changing oracle [brief §§5.1–5.4][brief]. |
| Numerical assets | Pinned reference-generated BF16 RoPE for positions 0–131071, 32 active pairs, both cosine/sine (16 MiB payload by layout arithmetic); exact frequency construction, input evaluation precision, rounding point, layout/endianness and generator identity. Bounded BF16-input GELU (`approximate="none"`), SiLU, sigmoid and raw-logit→FP32 softcap tables require declared domain/all covered input bit patterns, exceptional-value policy and output dtype. XSA `tanh(alpha)` values require parameter/input identity and producer settings. No current generator output is claimed [brief §§3.5, 3.8, 3.11–3.12][brief], [ADR-0003][adr3]. |

The producer manifest must identify **the actual lane that produced each asset**. Establish its agreement with the accepted operational operation/output before qualification; do not call a native CPU-generated table “CUDA-derived.” Non-NaN FP32→BF16 conversion is exact RNE including signed zero/infinity/subnormal/tie boundaries; arithmetic NaNs canonicalize to `0x7FC0`, while checkpoint bytes remain unchanged. Compare NaN classification when reference payloads are unspecified. Nonfinite model logits on finite qualified inputs still fail. Tables do not qualify surrounding GEMM/attention [ADR-0003][adr3].

**Proposed bounded pilot, not release qualification:** freeze a small approved fixture pack covering the families above, at least one local-window crossing, both MUDD sites, prefill plus cached decode, Unicode, greedy and explicit-seed multi-choice streaming/non-streaming and termination. Predeclare finite request/context/output budgets and **three same-profile repetitions**, including one fresh process launch. Three is an audit/repeatability diagnostic choice, not a statistical independence or confidence guarantee. Long/full-context and exhaustive public API tests remain explicit later coverage, never silently marked passed by the small pilot.

Pilot acceptance requires:

1. Operator-authorized access, successful ordinary root-runtime launch, fully verified assets, observed complete fingerprint and hashed immutable bundle. No unlabelled eager substitution or missing producer identity.
2. Every planned fixture has a terminal record or explicit failure; request/IDs/text/logprobs/stops/usage can be traced to inputs and lane. There is a reproducible consumer recipe and independent transfer-integrity check.
3. Same-profile same-input/parameter/seed requests repeat accepted IDs/text/termination/usage, and the frozen numerical metrics quantify logit repeatability across repetitions/relaunches. Freeze the metric definitions before comparison: dtype, full-vocabulary inclusion, absolute-error aggregation/quantile convention, distribution normalization/KL direction/precision, margin/tie policy and selected positions. Report maximum as well as summary repeatability drift; do not assume exact logit bits.
4. Any observed drift is investigated under the unchanged numerical ceilings. If CUDA repeatability makes those gates unusable, record the reference as unsuitable/pending and isolate the cause (profile drift, kernels, batching, captures or assets), not widen thresholds or choose a favorable diagnostic oracle. Inter-profile changes are not same-profile repeat failures, but must be separately identified and cannot be pooled.
5. Separately labelled diagnostic/producer evidence is sufficient to identify known gaps; absent numerical assets/intermediates do not become invented outputs. A pilot that only proves serving/access is explicitly a partial pilot, not acceptance of the complete reference bundle.

**Full downstream numerical acceptance remains:** frozen ≥10,000 teacher-forced positions with mathematical prompts, reasoning, LaTeX, long contexts, local-window boundaries, both MUDD layers and EOS-adjacent coverage; finite logits; mean absolute softcapped error ≤0.02; p99 absolute error ≤0.15; mean reference→Vulkan KL ≤0.001; p99 position KL ≤0.01; ≥99.9% top-token agreement where reference top-two margin >0.1. These accepted ceilings are not measured outcomes, nor a new tolerance automatically applicable to all intermediates [ADR-0003][adr3], [brief §5.5][brief]. Windows/Linux reports stay separate.

## 6. Prospective paired quality manifest and one-look policy

**Required, not current functionality:** a versioned qualification manifest must precede claim-bearing outputs. It links the reference capture, verified source and native lossless artifact; complete frozen `math-extended` corpus; actual rendered bytes/token IDs and gold; every taskset/member/rollout ID and overlap; scorer code/vendor hashes, anchors/fallbacks and unavailable reasons; explicit sampler, decode, stops and budgets; candidate/platform/profile; seed-generation record; dependence graph and cluster weights; completeness expectation; analysis/precision definitions; pilot exclusion; final look and error allocation [ADR-0005][adr5], [ADR-0008][adr8]. A numerically captured reference corpus and the complete quality corpus are different inventories. Do not equate 10,000 teacher-forced positions with complete mathematical-suite qualification.

**Seed record:** declare the actual supported seed space and distribution, random generator/version, private entropy provenance where applicable, generation timestamp before outcomes, resulting immutable seed-manifest digest, and one independently drawn seed **with replacement** per paired request. Give the same draw to CUDA/Vulkan for that pair; derive choices as required by serving semantics. Accidental duplicate values from independent draws are valid; deliberately reusing a draw creates dependence, and uniqueness-by-rejection changes the experiment. A seed list's existence or distinct values do not prove independent draws. Preserve legacy base-seed/offset behavior outside strict qualification: the [runner][runner] currently uses `base_seed + problem_index * group_size + rollout_index`, not this prospective experiment [confidence policy][confidence].

**Execution/dependence record:** independent seeds only imply independent request-pair outcomes if each outcome depends on its own draw and frozen conditions. Dynamic batching, completion lengths, shared cache/state, scheduling and kernel selection can connect requests. Record actual request/batch/run membership, stream/reset policy, shared seeds/completions/randomness and outcome-affecting state, merging transitive connections. Isolation must not replace the accepted normal CUDA numerical profile with eager diagnostics. If only batches or complete runs have defensible independence, use those larger clusters. Repeated problem text alone is not dependence on the fixed corpus; one reused completion counted in multiple tasksets belongs to one cluster with all membership weights. Distinct seeds, successful repeatability and a one-off run are not independence proofs [confidence policy §§independence, prerequisites][confidence].

**Accepted deduction:** with `T` fixed tasksets, `n_t` problems and `k_ti` declared rollouts, define paired headline correctness loss `D_tir = C_tir − V_tir ∈ [−1,1]`, weight `a_tir = 1/(T n_t k_ti)` and estimate `delta_hat = Σ a_tir D_tir`. Each taskset receives equal weight. For independent clusters with mass `B_g = Σ_(tir∈g) a_tir`, the selected [Hoeffding theorem][hoeffding] application is:

`U_alpha = min(1, delta_hat + sqrt(2 log(1/alpha) Σ_g B_g²))`.

At the **one predeclared final look per platform/candidate**, complete compatible coverage and justified assumptions are mandatory; use `alpha = 0.05` and require `U_alpha ≤ 0.02`. It is expected stochastic correctness on the frozen corpus, not unseen-problem performance. The guarantee is over prospective randomization/execution, not conditional 95% coverage for every fixed seed list. Replaying the same reference seeds is repeatability evidence, not extra observations. Whole-suite independent repetitions require fresh paired CUDA **and** Vulkan executions [confidence derivation][confidence].

For the severe-taskset family, let `b_tg = Σ_(tir∈g) 1/(n_t k_ti)`. With `beta = 0.05`, predeclare Bonferroni lower bounds:

`L_t = max(−1, delta_hat_t − sqrt(2 log(T/beta) Σ_g b_tg²))`.

Any unresolved `L_t > 0.05` blocks release even if the macro gate passes; fix/requalify rather than compensate with other tasksets. A non-triggering lower bound does **not** establish taskset loss ≤0.05, and missing results do not count as non-triggering success [ADR-0008][adr8], [confidence severe-taskset rule][confidence]. Preserve every grader view; select only the declared headline anchor/fallback.

**Error accounting:** freeze final observation count, cluster masses, candidate and final analysis before qualification data. Pilot outputs are exploratory and excluded, not promoted after a favorable result. Any further claim-bearing looks require preallocated levels (e.g. `Σ alpha_j ≤0.05` for the relevant overall claim family and separate severe-family allocation), or a justified sequential method. Repeated ordinary 95% bounds until passing are invalid. Separate Windows/Linux 95% claims and the overall/severe families do not imply one joint 95% guarantee; explicitly declare the family if making a joint claim [ADR-0008][adr8], [confidence looks policy][confidence]. Use conservative unrounded bounds for gates.

**Planning arithmetic only:** at zero observed loss, equal independent cluster mass would need `N_eff = 1/Σ B_g² ≥ 2 log(20)/0.02²`, approximately **14,979**. This is not a powered workload or access/cost promise. Unequal weights/larger clusters reduce precision. Suite-wide unresolved dependence yields one cluster and only `U=1`; no useful qualification claim is supported. More deterministic reruns or bootstrap resamples do not repair that evidence gap [confidence][confidence].

## 7. Failure handling, privacy and redistribution

**Required failure policy:** checksum/source/profile mismatch quarantines the attempt; retain immutable logs and original outputs. Interrupted/transport-retried requests need attempt IDs and linkage: a resend is not a new independent rollout, and outcome selection cannot favor the successful-looking completion. The existing runner already records transport retries [runner][runner]; the strict experiment must preserve their possible shared execution/state effects. Missing coverage, grader availability, unsupported parameters, missing raw-ID evidence or unresolved cluster provenance remain pending, not zero losses or passes. Investigate reference disagreements without switching references. Fixes/profile changes create new identified candidates/attempts and must respect predeclared look accounting.

**Source licensing:** the pinned [model card][card] declares weights Apache-2.0 and serving code Apache-2.0; the repository [license][license] requires license distribution, retained applicable notices/attribution, change notices and applicable NOTICE preservation. That does not license every benchmark item, vendored scorer, CUDA binary or operator's private inputs. Before public bundle publication, inventory each dataset/scorer/source/runtime license and access restriction at its resolved identity; obtain needed redistribution permission. If unresolved, retain approved content privately and publish hashes, schema, aggregate evidence and authorized acquisition instructions, not protected problems/gold/completions or binaries. Digests establish identities only when an authorized verifier can obtain the underlying inputs. Derived tables/fixtures require documented provenance and redistribution assessment; do not assume they inherit a universal permission.

**Required privacy boundary:** use approved non-personal synthetic/public pilot prompts. Private benchmark/customer prompts, answers, completions and machine identifiers stay in controlled storage with access/retention rules. Publish allowlisted/redacted environment records, not HF/API/SSH credentials, shell history, tokens, internal hostname/path identifiers or arbitrary full environments. Hash the retained originals; identify any redacted public derivative separately so redaction is not disguised as identical source evidence. Restriction of public access does not justify skipping full private verification.

## 8. Reuse, gaps and resolution

| Classification | Finding |
|---|---|
| Reusable source-established contract | Root lock/plugin, fixed HF target, accepted reference hierarchy, numerical ceilings, canonical Python text ownership, full serving surface, existing immutable evaluation inputs/journal conventions and selected confidence policy. |
| Conditional route | Authorized Linux/NVIDIA operator can attempt ordinary root capture; structural code/producer tables aid diagnosis only with actual fingerprints and measured agreement. Independent request clusters are usable only with justified execution isolation/state provenance. |
| Unexecuted obligations | Full model/text byte verification, installed/loaded binary identity, attention/compiler/graph profile, complete capture tooling/event/producer access, repeatability, metric/corpus/seed/dependence manifest, licensing review and paired platform runs. |
| Unavailable evidence | No authorized operational CUDA runner established here; no GPU outputs, numerical assets, independent random-seed execution, repeatability bound, measured quality loss or platform-support result. HF API/raw requests returned HTTP 429 during research; pinned rendered card/config/weight-pointer pages were readable, but complete weights and text blobs were not downloaded/hashed here. The original Hoeffding PDF extractor returned incomplete text; the immutable confidence note records prior theorem-page inspection and supplies the accepted derivation. |

**Issue resolution:** [Define CUDA reference capture and qualification prerequisites](https://github.com/GreenYellowRedBlue/limite-violetto/issues/6) can close as a source-research question with this report. The operational reference is ordinary root vLLM 0.26.0 at the fixed target, not native Transformers diagnostics or the historical 0.28 evaluator. A valid bundle needs complete verified assets, producer/execution fingerprints, separate raw token/text/logprob/termination evidence and measured same-profile repeatability. Strict quality also requires the frozen corpus, prospective randomized paired seeds, justified clusters, complete coverage and one-look/severe-family accounting. [Verify an operational CUDA reference capture bundle](https://github.com/GreenYellowRedBlue/limite-violetto/issues/12) and [Define the native token-control and serving conformance boundary](https://github.com/GreenYellowRedBlue/limite-violetto/issues/14) remain unresolved. Actual producer/repeatability failures may expose a concrete later question without reopening accepted policies.
