# BF16 operation-boundary evidence in the pinned Vulkan backend

## Scope and identities

This report answers [Determine BF16-semantic gaps in the pinned Vulkan backend](https://github.com/GreenYellowRedBlue/limite-violetto/issues/2) from source evidence only. Target model source is the official [Violetto snapshot](https://huggingface.co/paradigma-inc/limite-1b-violetto/tree/9f4d1567975a44c35127503deadfe52d434d734f) `9f4d1567975a44c35127503deadfe52d434d734f`; original plugin source is `7ddad34f5e3d25ddea68c6745fc00373b82bca21`, and accepted immutable specification/ADRs are [context commit `173c50ea1f11b4b68ad8eb350b40c8b464ae64d5`](https://github.com/GreenYellowRedBlue/limite-violetto/tree/173c50ea1f11b4b68ad8eb350b40c8b464ae64d5). Candidate llama.cpp `296538adea19ff397100bf8e7d71f302d2d2bb35` is not qualified. Root CUDA/vLLM 0.26 remains operational comparator; [ADR-0003](https://github.com/GreenYellowRedBlue/limite-violetto/blob/173c50ea1f11b4b68ad8eb350b40c8b464ae64d5/docs/adr/0003-separate-operational-and-structural-references.md) keeps native/eager/structural diagnostics separate.

The accepted ADR requires non-NaN RNE conversion including signed zero, infinities and subnormal boundaries, arithmetic NaNs canonicalized to quiet BF16 `0x7FC0`, and distinct preservation of serialized checkpoint bytes. It also requires capturing reference behavior rather than inferring CUDA payload/denormal behavior. The source hierarchy and precision exceptions are constraints, not measurements.

The candidate shader helper arithmetic reproduction is useful to falsify the assumption that the helper's simple RNE bit adjustment canonicalizes all NaNs; it is not a substitute for running a shader or for operational CUDA comparison. Likewise, a BF16 storage/support flag, CPU conversion helper, or advertised BF16 cache is not model-wide validation.

## Falsifying diagnostic checks

1. Compare a dedicated shader conversion kernel against the accepted conversion oracle on exact ties (both retained-LSB parities), nextafter neighbors, positive/negative zero, smallest/largest subnormals and normal transition, infinities, signaling/quiet NaNs with varied payload/sign. Capture actual output bits; separately classify algorithm reproduction and shader execution. Check arithmetic NaNs against `0x7FC0`; do not conflate serialized bytes.
2. Exercise each selected Vulkan pipeline with exact model shapes and BF16/F32/F16 types, including elementwise add/sub/mul/div, RMSNorm/unary, row/copy, matrix, attention/KV and each fusion. Confirm generated shader, pipeline selection, intermediate types and explicit conversion sites; a supports-op response alone is not sufficient.
3. Instrument layer boundary values against the operational CUDA capture: norm epsilon and reduction, FP32 XSA calculations and narrowing, QKV/O scale folding, every ordered MUDD tap multiply/add, LUT producer output, tied head and FP32 softcap. Include representative exceptional values and rounding-sensitive inputs; record actual backend/precision/compile settings as ADR-0003 requires.
4. Compare unfused/fused executions at required boundaries and diagnose any mismatch rather than assuming algebraic equivalence. Verify serialized checkpoint bytes independently from derived/folded effective weights.

## Resolution and limits

The source question is answered: the candidate provides relevant BF16 storage and selected compute paths, but does not establish Violetto's complete required BF16 operation-boundary semantics. The helper's source algorithm lacks canonical NaN handling; elementwise/norm shader variants shown are F32/F16; scalar ordering, FP32 exceptions, LUT production and exact GEMM/attention/fusion behavior need explicit mapping and diagnostics. The evidence identifies reusable mechanisms and conditional paths, not a new numerical policy or feasibility conclusion.

No build, test, GPU dispatch, shader execution, operational reference capture, full checkpoint byte verification or platform qualification was performed for this report. It makes **no claim of complete kernel/GPU feasibility**. Downstream [Test BF16 and shader boundaries in isolated diagnostics](https://github.com/GreenYellowRedBlue/limite-violetto/issues/10) remains the evidence vehicle; source research is resolved while downstream feasibility and semantic qualification remain unvalidated.
